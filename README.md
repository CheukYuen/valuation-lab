# valuation-lab

学会**审**估值，而不是学会**做**估值。

建一个 DCF 需要判断未来七年的收入、利润率和资本开支。审一个 DCF 不需要——因为**估值错误几乎不发生在数学里，发生在接缝上**：口径、时点、分母、信息性质。接缝可以肉眼查。

本仓库不产出投资结论，只训练判断力。它不输出目标价、评级、仓位或买卖动作。

## 五分钟上手

```bash
python3 lab/mini_dcf.py
```

40 行的最小 DCF。看输出最下面的**弹性排序**：折现率的权力是增长率的三倍，而研报里增长率讨论十页、折现率写在附录一行。

```bash
python3 lab/reverse.py 300
```

反解。不问「值多少钱」（你答不了），问「现在的价格要求什么」（你能拿历史去查）。这是从零起步最短的一条路。

零依赖，只用 Python 标准库。

## 学习路径

| 阶段 | 做什么 | 判断自己过关了没有 |
|---|---|---|
| 一 | 反复跑 `lab/mini_dcf.py`，每次只改一个输入 | 不跑程序也能说出哪个假设在决定结论 |
| 二 | 跑 `lab/reverse.py`，改折现率看要求怎么变 | 拿到任何价格，能把它翻译成一个可查证的经营条件 |
| 三 | 读 `docs/`，做 `cases/01-yofc`，审完再对答案 | 漏掉的项能区分「不知道该查」和「查不动」 |
| 四 | 拿真实研报按清单审 | 能在读结论之前就判断这份材料值不值得读 |

第三阶段是重点。**审完自己的记录再打开答案**，否则案例就浪费了。

## 与 investment-research-copilot 的关系

那个仓库做真实研究并产出估值运算，这个仓库训练审它的能力。

`cases/01-yofc/frozen/` 是从那边**冻结复制**的一份运算（来源提交 `b7c2da0`）。冻结而不是引用，因为教学案例必须不动：那边按约定会新建 `as_of` 目录，而且如果模型按审计意见修好了，答案就会指向一个不存在的问题。

单向依赖，只读，不同步回去。
