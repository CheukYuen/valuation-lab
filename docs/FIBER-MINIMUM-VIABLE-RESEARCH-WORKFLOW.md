# 一个人的最小有效投研流程：以光纤为例

> 一个人负责定义问题、边界和判断标准，Agent负责持续收集、结构化、计算、比较和验证。目标不是做一个资料库，而是持续回答四个可证伪的问题：行业利润池往哪里走，公司能拿到多少并转成多少现金，当前价格已经计入多少，什么证据会证明我们错了。

## 先看结论

### 最核心的是四个问题，不是三个

1. **行业利润池往哪里走？** 哪个需求池、产品规格和供需缺口正在创造收入与利润。
2. **公司能拿到多少并变成多少现金？** 公司有哪些真实产品暴露、有效产能、客户和成本优势，利润是否被Capex与营运资金吃掉。
3. **当前价格已经计入多少？** 股价隐含了多高的销量、ASP、利润率、增长期和资本回报率。
4. **什么证据会证明我们错了？** 用哪些领先指标、财务结果和失效条件持续验证。

前三问分别对应基本面、公司兑现和预期差；第四问让结论可以被证伪。缺少第三问，只能得到“行业/公司好不好”，不能判断价格是否还有预期差；缺少第四问，结论会变成无法退出的故事。

### 正确结构不是“行业和产业链谁先”

完整顺序是：

`终端场景/系统变化 -> 产品与规格 -> 行业供需和利润池 -> 产业链利润分配 -> 公司利润与现金捕获 -> 价格隐含预期 -> 验证`

但在开始分析前，要先画一张很粗的产业链物理地图，用来定义研究边界。因此实际工作是一个小闭环：

`粗产业链地图（定边界） -> 产品行业供需（利润池多大） -> 回到产业链（利润由谁拿走）`

所以，“先看产业链环境，再看行业”只对了一半：可以先用产业链定位，但不能在没有定义产品和供需市场之前判断利润分配。

Agent最终维护一张地图和五张表：

1. **场景-产品-产业链地图**：定义终端、产品规格、生产环节和研究边界；
2. **行业利润池表**：记录分产品需求、有效供给、缺口和ASP；
3. **产业链利润分配表**：记录瓶颈、议价权、单位利润和现金流向；
4. **公司利润桥**：把公共行业事实映射到公司销量、利润和FCFF；
5. **预期与估值表**：记录市场价格隐含条件及三种情景；
6. **证据与验证表**：记录来源、状态、失效条件和下一验证指标。

## 1. 先把几个容易混淆的对象分开

### AI数据中心不是光纤行业

- **AI数据中心**是终端应用场景和系统。
- **光连接**是这个系统中的功能模块。
- **G.652.D、G.657、特种光纤、光缆、连接器**是具体产品或规格。
- **光纤行业**是同类产品的需求、供给、产能和价格市场。
- **光纤产业链**描述从设备/原料、预制棒、光纤拉丝、光缆/组件到终端客户的生产和议价关系。
- **长飞、中天**是处在链条不同位置、业务暴露不同的公司。

这些对象不是同一级菜单。先从终端变化向下翻译成产品需求，再进入相应产品行业；不能把“AI数据中心增长”和“光纤行业增长”直接画等号。

### 一条可计算的因果链

`数据中心Capex/运营商网络建设`

`-> 网络架构、BOM和产品规格变化`

`-> 各规格fiber-km/芯公里/端口需求`

`-> 可服务该规格的合格有效产能`

`-> 供需缺口、合同价格和ASP`

`-> 产业链各环节单位利润与议价权`

`-> 公司销量、产品结构、毛利率和订单确认`

`-> Capex、存货、应收和FCFF`

`-> 估值与价格隐含预期`

任何信息若不能进入这条链，Agent先放入候选资料区，不直接改变结论。

## 2. 第一步：用粗产业链地图定义边界

### 物理链

`设备/原材料 -> 预制棒 -> 光纤拉丝 -> 光缆/连接组件 -> 网络设备/施工 -> 运营商/数据中心/海外客户`

这一步不判断谁最赚钱，只回答：

1. 终端变化需要什么产品；
2. 产品经过哪些生产环节；
3. 哪些规格共用产能，哪些完全不共用；
4. 研究对象的上游约束和下游客户是谁。

### 产品兼容性是第一道失败门

只有同时满足以下条件，两个需求池才可能争夺同一供给并共同影响ASP：

- 产品规格可替代或共用关键工艺；
- 使用相同的预制棒、拉丝、设备或认证产能；
- 产线可以在合理时间和成本内切换；
- 产品能进入相同客户市场。

普通通信光纤、G.657、HCF、海缆和连接组件不能因为都含“光”就合并成一个需求池。

## 3. 第二步：按产品行业计算利润池

### 最小问题

1. 终端需求转化成多少可比产品需求？
2. 当前合格有效供给是多少？
3. 新增供给何时真正建成、爬坡、认证并可销售？
4. 供需差体现在哪一种合同价格、招标价或公司ASP？
5. 价格变化扩大或压缩了多少行业毛利润？

### 场景-产品-行业利润池表

| 终端场景 | 产品/规格 | 可比单位 | 需求证据 | 共用有效产能 | 价格指标 | 当前利润池判断 |
|---|---|---|---|---|---|---|
| 运营商骨干/接入网 | G.652.D等普通通信光纤 | fiber-km | 运营商招标量 | 预制棒、拉丝、认证 | 集采价/公司ASP | 待填 |
| 数据中心互连 | G.657、特种光纤、连接方案 | fiber-km/芯公里/端口 | 客户订单、认证、Capex与BOM | 只计相同工艺与合格产能 | 合同价/产品ASP | 待填 |
| 海外通信 | 按地区和产品拆分 | fiber-km | 海外运营商/公司披露 | 出口认证与渠道 | 出口ASP | 待填 |
| 技术期权 | HCF等新产品 | 订单/交付/收入 | 认证、初始订单、量产收入 | 不能提前并入普通产能 | 实际合同价 | 待填 |

### 三条硬规则

- 宣布产能不等于建成产能，不等于合格有效产能。
- 招标最高限价或中标价不等于公司综合ASP。
- 普通光纤、G.657、HCF和海外产品不能拼成一条价格序列。

## 4. 第三步：回到产业链判断利润由谁拿走

行业供需只说明利润池变大或变小，不说明每个环节都能同比例受益。现在再沿产业链回答：

| 问题 | 要记录什么 |
|---|---|
| 谁是瓶颈 | 设备交期、原材料、良率、认证、客户导入或施工能力 |
| 谁能提价 | 合同重定价周期、客户集中度、替代品和库存 |
| 谁必须先花钱 | Capex、在建工程、存货、应收和履约资产 |
| 谁拿到利润 | 单位毛利、利用率、产品结构和成本传导 |
| 谁拿到现金 | 预付款、回款周期、库存和应收变化 |

这一层的输出不是公司名单，而是一条利润传导路径：

`哪个产品先短缺 -> 哪一环先提价 -> 上下游能否转嫁 -> 哪一环利润率上升 -> 现金何时收到`

## 5. 长飞和中天哪些数据可以共用

最有效的做法不是为两家公司分别采集一遍行业数据，而是建立一份“光纤行业公共事实层”，再分别建立公司暴露映射。

### 可以共用的公共事实层

| 数据 | 为什么可以共用 | 使用边界 |
|---|---|---|
| 运营商招标量、批次和对应产品规格 | 两家公司都可能参与通信光纤/光缆市场 | 必须再乘各自中标份额、产品范围和收入确认时点 |
| G.652.D、G.657等分规格价格 | 描述同一产品市场的价格环境 | 不能直接当成任一公司的综合ASP |
| 全球/中国分产品需求 | 描述共同的终端需求池 | 需要检查两家公司实际产品和地区暴露 |
| 预制棒、拉丝和光缆有效产能 | 描述共同供给环境 | 必须区分宣布、建成、爬坡、合格和可销售产能 |
| 扩产项目、设备交期、良率和认证进度 | 影响共同供给曲线 | 不同工艺、规格和客户认证不能互换 |
| 上游原材料、能源和关键设备 | 影响行业成本或扩产速度 | 两家公司自供比例、采购合同和成本敏感度不同 |
| 贸易政策、出口市场和汇率环境 | 影响行业出口机会与价格 | 两家公司出口地区、币种和客户结构不同 |
| 数据中心/运营商的系统和BOM变化 | 是产品需求的共同上游驱动 | 必须翻译到具体规格和单位，不能直接外推公司收入 |

公共事实只能记录一次，但必须带：产品规格、地区、单位、期间、来源、页码、实际/预测状态和 `as_of`。

### 只能条件共用的数据

| 数据 | 条件 |
|---|---|
| ASP | 只有产品、地区、合同类型、含税/运费口径和期间一致才可比较 |
| 产能 | 只有工艺、规格、良率、认证和客户市场兼容才算共同供给 |
| 招标价格 | 只适用于对应运营商、批次和产品，不能覆盖特种/海外业务 |
| 数据中心需求 | 只有能够落到两家公司实际销售的产品与认证客户时才进入公司模型 |

### 不能共用的公司层数据

| 长飞 | 中天 |
|---|---|
| 预制棒-光纤-光缆一体化比例 | 光通信、电力传输、海洋系统的业务权重 |
| 普通/特种光纤销量和公司ASP | 各业务订单、交付和收入确认节奏 |
| 自有有效产能、利用率、产品良率 | 光通信有效产能及电力/海洋项目执行能力 |
| A/H股本、价格、汇率和证券口径 | A股股本、净债务和估值口径 |
| 公司单位成本、客户、Capex和营运资金 | 公司单位成本、客户、Capex和营运资金 |

一句话概括：**行业观测值可以共用，公司影响函数不能共用。** 同一条G.657价格变化，要分别经过长飞和中天的产品暴露、销量、合同、成本、业务权重和确认时点，才能进入各自利润表。

## 6. 第四步：公司利润和现金捕获

### 公司利润桥

`分产品收入 = 销量 × 公司ASP`

`毛利润 = 各产品收入 × 各产品毛利率`

`EBIT -> NOPAT -> +折旧摊销 - Capex - 营运资金增加 = FCFF`

### 长飞和中天的不同映射

- **长飞**：重点围绕预制棒-光纤-光缆一体化、普通与特种产品结构、自产/外购、有效产能和A/H证券口径。
- **中天**：必须把光通信、电力传输和海洋系统分开。光纤行业公共层只能进入光通信业务；海洋订单确认和电力业务利润率需要各自的数据链。

### 最小公司表

| 变量 | 历史事实 | 公司指引 | 一致预期 | 券商预测 | Agent情景假设 | 下一验证指标 |
|---|---:|---:|---:|---:|---:|---|
| 销量/交付 |  |  |  |  |  | 招标、订单、交付 |
| ASP/项目单价 |  |  |  |  |  | 合同、渠道、收入/销量 |
| 产品结构 |  |  |  |  |  | 分部收入、认证、客户 |
| 单位成本/毛利率 |  |  |  |  |  | 原料、利用率、毛利率 |
| Capex |  |  |  |  |  | 在建工程、现金流量表 |
| 营运资金 |  |  |  |  |  | 存货、应收、预付款 |

事实、指引、一致预期、券商预测和Agent情景必须分列。缺失写 `MISSING`，Agent不得用一条新闻自动补齐。

## 7. 第五步：估值回答价格已经相信什么

最小组合是：

1. **FCFF DCF**：把利润转成现金价值，明确Capex和营运资金代价；
2. **相对估值**：检查市场如何给目标期盈利定价，不代替现金流；
3. **反向DCF**：反求当前股价需要的利润率、增长期或资本回报率；
4. **SOTP**：只在公司业务确实异质、分部数据足够时使用。

不同方法回答不同问题，不平均目标价。周期高点利润放在显性期，终值使用正常化利润率和可持续再投资回报。

最小输出不是“合理价是多少”，而是：

- 当前价格隐含的销量、利润率和高增长持续期；
- 基准/上行/下行情景分别依赖哪些事实；
- 最能改变估值的两个变量；
- 当前事实与市场隐含条件之间是否存在差异。

## 8. 第六步：验证和证伪

### 一条可证伪结论的写法

“如果普通光纤和G.657需求增长继续快于合格有效产能，且公司新合同ASP上升并转化为现金，则未来四个季度毛利率和FCFF改善；如果新增产能提前通过认证、招标价回落或存货/应收继续上升，则结论失效。”

### 验证表

| 假设 | 领先指标 | 财务验证 | 失效条件 | 频率 |
|---|---|---|---|---|
| 供需仍紧 | 招标量、交期、渠道价、库存 | 公司ASP/毛利率 | 价格和交期同步回落 | 月/季 |
| 有效产能爬坡慢 | 设备、点火、良率、认证 | 产量、利用率、折旧 | 合格产量快速释放 | 月/季 |
| 产品结构改善 | 认证、特种订单、交付 | 分部收入和毛利率 | 高价订单不确认收入 | 季 |
| 利润变成现金 | 预付款、回款 | OCF、存货、应收、Capex | 利润升而FCFF持续恶化 | 季 |

## 9. Agent自动执行流程

### 人负责一次性定义的内容

1. 研究对象和边界：哪个终端场景、产品、地区和公司；
2. 核心问题和因果链；
3. 允许使用的来源、证据等级和时点规则；
4. 哪些输入可以成为事实，哪些只能作为情景假设；
5. 需要人工确认的重大变化和失效条件。

这些规则确定后，日常运行可以由Agent自动完成。

### Agent每次运行的状态流

`读取上次快照`

`-> 检索新增公司公告、行业数据、招标、价格、产能和研报`

`-> 抽取原始值、单位、期间、来源、页码、状态和as_of`

`-> 按终端场景/产品/行业/产业链/公司归类`

`-> 更新光纤行业公共事实层并做产品兼容性检查`

`-> 分别映射到长飞和中天的公司暴露与利润桥`

`-> 重算经营情景、FCFF、估值和反向DCF`

`-> 与上次运行比较，识别假设变化、矛盾和失效条件`

`-> 输出变化摘要、证据链、缺失项和需要人工判断的问题`

### Agent可以自动完成

- 查找、下载和去重授权范围内的新资料；
- 表格/正文抽取、单位/币种/期间和A/E状态标准化；
- 更新公共行业事实层及两家公司映射；
- 公式复算、情景敏感性和反向DCF；
- 新旧预测误差分解；
- 监控失效条件并只报告重要变化；
- 保存本次输入快照、来源、计算结果和差异。

### Agent必须停下或降级结论

- 产品规格、地区、价格口径或期间无法对齐；
- 宣布产能无法证明已成为合格有效产能；
- 只有标题、二手转述或无法定位原文页码；
- 公司分部暴露、收入确认或现金流桥缺失；
- 新证据与已有事实冲突，且无法解释差异；
- 需要把 `MISSING` 变成假设才能给出结论。

Agent可以自动提出情景，但必须标为 `AGENT-ASSUMPTION`，不能升级为 `ACTUAL`、`GUIDANCE` 或 `CONSENSUS`。

## 10. 一个人怎样使用自动化结果

### 初次建档

人只需要确认：研究边界、核心因果链、证据规则、公司分部和失效条件。Agent建立公共行业层、公司映射、估值底稿和首个证据快照。

### 每日/每周

Agent自动运行，只在以下情况提醒：

- 关键事实或价格发生变化；
- 结论依赖的假设需要修改；
- 公司实际结果偏离原预测；
- 失效条件被触发；
- 出现无法自动解决的证据冲突或 `MISSING`。

人阅读的不是全部新闻，而是一页“变化了什么、为什么影响利润和现金、估值变化多少、需要决定什么”。

### 每季

Agent自动用实际收入、毛利率、Capex和营运资金对照原预测，将误差归因到销量、ASP、结构、成本或确认时点，并更新正常化利润率和终值假设。人只审核重大判断变化。

公共证据只采集一次，公司影响分别计算；每次运行保存当时可见的输入和结果，避免用今天的信息悄悄改写过去判断。

## 12. 停止规则

满足以下任一条件，Agent停止扩展检索或将任务交给人：

1. 新资料不改变销量、ASP、成本、Capex、营运资金或估值参数；
2. 同一结论已有两个相互独立的一手/高质量来源；
3. 关键缺口只能靠未披露数据解决，此时明确写 `MISSING`；
4. 当前价格在合理情景下都没有明显预期差；
5. 失效条件已经触发，先推翻旧结论再研究新故事；
6. 不同产品、地区、期间或证据状态无法安全归一。

这套流程的“最小有效”不在于Agent搜了多少资料，而在于每次运行都能从终端变化走到产品行业利润池、产业链利润分配、公司现金流和价格隐含预期，并保留可以推翻结论的证据。
