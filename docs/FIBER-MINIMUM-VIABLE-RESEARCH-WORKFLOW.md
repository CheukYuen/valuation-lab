# 一个人的最小有效投研流程：以光纤为例

> 目标不是建立一套“看起来专业”的大系统，而是让一个人用最少的固定动作，持续回答一个可证伪的问题：行业利润池往哪里走，这家公司能拿到多少，当前价格已经计入多少。

## 先看结论

一个人的最小有效流程只保留五张表和一个结论：

1. **行业利润池表**：需求、有效供给、缺口、ASP；
2. **产业链地图**：谁掌握瓶颈，价格变化由谁拿走；
3. **公司利润桥**：销量、ASP、结构、成本如何变成利润和FCFF；
4. **预期与估值表**：市场价格隐含什么，不同情景值多少；
5. **证据与验证表**：每个关键假设用什么指标证伪；
6. **一句话结论**：驱动、分歧、价格隐含条件、下一证据。

不需要先收集“所有资料”。先写因果链，再只找能改变关键变量的证据。

## 1. 先把问题缩到一条因果链

以光纤为例：

`数据中心/运营商需求 -> 产品规格与fiber-km需求 -> 合格有效产能 -> 供需缺口 -> ASP和产品结构 -> 公司销量与毛利率 -> Capex/营运资金 -> FCFF -> 估值`

任何信息若不能进入这条链，先不研究。例如“AI需求很好”太宽；要继续追问：需要哪种光纤、多少fiber-km、与通信光纤是否共用预制棒和拉丝产能、谁已认证、何时确认收入。

## 2. 行业：只做利润池，不做新闻汇编

### 最小问题

1. 终端需求来自哪里，单位是什么？
2. 需求对应哪种产品规格？
3. 当前有效供给是多少，新增供给何时真正可销售？
4. 供需差最终体现为哪个价格？

### 行业利润池表

| 需求池 | 产品/规格 | 可比单位 | 需求证据 | 共用有效产能 | 价格指标 | 当前判断 |
|---|---|---|---|---|---|---|
| 运营商骨干/接入网 | G.652.D等普通通信光纤 | fiber-km | 运营商招标量 | 预制棒、拉丝、认证 | 集采价/公司ASP | 待填 |
| 数据中心互连 | G.657、特种光纤、连接方案 | fiber-km/芯公里/端口 | 客户订单、认证、Capex与BOM | 只计相同工艺与合格产能 | 合同价/产品ASP | 待填 |
| 海外通信 | 按地区和产品拆分 | fiber-km | 海外运营商/公司披露 | 出口认证与渠道 | 出口ASP | 待填 |
| 技术期权 | HCF等新产品 | 订单/交付/收入 | 认证、初始订单、量产收入 | 不能提前并入普通产能 | 实际合同价 | 待填 |

### 三条硬规则

- 宣布产能不等于建成产能，不等于合格有效产能。
- 招标最高限价或中标价不等于公司综合ASP。
- 普通光纤、G.657、HCF和海外产品不能拼成一条价格序列。

## 3. 产业链：找瓶颈和利润归属

### 最小地图

`原材料/设备 -> 预制棒 -> 光纤拉丝 -> 光缆/连接组件 -> 运营商/数据中心/海外客户`

每一环只回答四件事：

| 问题 | 要记录什么 |
|---|---|
| 谁是瓶颈 | 设备交期、原材料、良率、认证、客户导入或施工能力 |
| 谁能提价 | 合同重定价周期、客户集中度、替代品和库存 |
| 谁要先花钱 | Capex、在建工程、存货、应收和预付款 |
| 谁拿到利润 | 单位毛利、利用率、产品结构和回款条件 |

产业链研究的输出不是公司名单，而是一句话：“供需变化先影响哪个环节的价格，利润多久后传到哪家公司，现金何时收到。”

## 4. 公司：从暴露度到利润捕获

### 长飞和中天为何不能套同一张公司表

- 长飞更适合围绕预制棒-光纤-光缆一体化、普通与特种产品结构、A/H股估值展开。
- 中天必须同时拆光通信、电力传输和海洋系统。光纤景气只能解释其中一部分；海缆订单确认和电力业务利润率有独立驱动。

### 公司利润桥

`收入 = 销量 × ASP + 其他业务收入`

`毛利润 = 各产品收入 × 各产品毛利率`

`EBIT -> NOPAT -> +折旧摊销 - Capex - 营运资金增加 = FCFF`

最小公司表：

| 变量 | 历史事实 | 公司指引 | 一致预期 | 自己假设 | 下一验证指标 |
|---|---:|---:|---:|---:|---|
| 销量/交付 |  |  |  |  | 招标、订单、交付 |
| ASP/项目单价 |  |  |  |  | 合同、渠道、收入/销量 |
| 产品结构 |  |  |  |  | 分部收入、认证、客户 |
| 单位成本/毛利率 |  |  |  |  | 原料、利用率、毛利率 |
| Capex |  |  |  |  | 在建工程、现金流量表 |
| 营运资金 |  |  |  |  | 存货、应收、预付款 |

事实、指引、券商预测和自己的假设必须分列。空格写 `MISSING`，不要用一条新闻补齐。

## 5. 估值：先问价格已经相信什么

最小组合是：

1. **FCFF DCF**：把利润转成现金价值，明确Capex和营运资金代价；
2. **相对估值**：检查市场如何给目标期盈利定价，不代替现金流；
3. **反向DCF**：反求当前股价需要的利润率、增长期或资本回报率；
4. **SOTP**：只在公司业务确实异质、分部数据足够时使用。

不同方法回答不同问题，不平均目标价。周期高点利润必须放在显性期，终值使用正常化利润率和可持续再投资回报。

## 6. 证据：只保留能推翻结论的指标

### 一条可证伪结论的写法

“如果普通光纤和G.657需求增长继续快于合格有效产能，且公司新合同ASP上升并转化为现金，则未来四个季度毛利率和FCFF改善；如果新增产能提前通过认证、招标价回落或存货/应收继续上升，则结论失效。”

### 验证表

| 假设 | 领先指标 | 财务验证 | 失效条件 | 频率 |
|---|---|---|---|---|
| 供需仍紧 | 招标量、交期、渠道价、库存 | 公司ASP/毛利率 | 价格和交期同步回落 | 月/季 |
| 有效产能爬坡慢 | 设备、点火、良率、认证 | 产量、利用率、折旧 | 合格产量快速释放 | 月/季 |
| 产品结构改善 | 认证、特种订单、交付 | 分部收入和毛利率 | 高价订单不确认收入 | 季 |
| 利润变成现金 | 预付款、回款 | OCF、存货、应收、Capex | 利润升而FCFF持续恶化 | 季 |

## 7. 一个人的实际节奏

### 第一次建档：半天到一天

1. 写一条因果链和一个可证伪问题；
2. 建五张空表，不追求填满；
3. 只读公司年报/中报、最近业绩会、关键招标和一至三份代表性研报；
4. 把每个数字标为 `ACTUAL / GUIDANCE / CONSENSUS / BROKER-EST / DERIVED / MISSING`；
5. 做一个三情景估值和一个反向DCF；
6. 输出一句话结论与三项下一证据。

### 每周：60-90分钟

1. 更新招标、价格、产能和公司公告；
2. 只改受新证据影响的表格和假设；
3. 记录“什么变了、为什么影响利润/现金、估值变多少”；
4. 没有改变关键变量的信息只入资料箱，不改结论。

### 每季：半天

1. 用实际收入、毛利率、Capex和营运资金对照原预测；
2. 把误差归因到销量、ASP、结构、成本或确认时点；
3. 更新正常化利润率和终值，而不是只上调下一年EPS；
4. 重写失效条件和下一季度验证指标。

## 8. 最小文件夹

```text
company/
  thesis.md          # 一句话结论、分歧、失效条件
  industry.md        # 需求、有效供给、ASP
  value-chain.md     # 瓶颈与利润归属
  company-model.csv  # 分部量价、利润、Capex、营运资金
  valuation.py       # DCF、相对估值、反向DCF
  evidence.csv       # 数字、单位、期间、来源、页码、状态
  review.md          # 每周/每季误差与更新
```

工具可以简单，口径必须严格。一个可复算的CSV和Python脚本，胜过不可追溯的复杂系统。

## 9. 停止规则

满足以下任一条件就先停，不继续堆资料：

1. 新资料不改变销量、ASP、成本、Capex、营运资金或估值参数；
2. 同一结论已有两个相互独立的一手/高质量来源；
3. 关键缺口只能靠未披露数据解决，此时明确写 `MISSING`；
4. 当前价格在合理情景下都没有明显预期差；
5. 失效条件已经触发，先推翻旧结论再研究新故事。

这套流程的“最小有效”不在于文件少，而在于每一步都能从行业事实走到公司现金流，再走到价格隐含预期，并且随时可以被新证据推翻。
