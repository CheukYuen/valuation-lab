# 记录契约样本：一次只触发一个失败状态

第1课开发者层的可选实验。十条虚构记录，公司和数字只用于教学。

**跳过它不影响完成第1课。** 纸面判断才是本课的正体，脚本只负责让「我的判断可以被复算」这件事成立。

## 怎么用

先不看 `expect_codes` 字段，自己读一遍记录，写下：

```text
失败状态：单家预测冒充共识 / 未来信息污染 / 内部调整无桥 / 证据指针缺失 / 尚未程序复核 / 明确错误 / 语义不完整 / 合规无需降级
证据：哪个字段让你这样判断
影响：它会挡住哪一步
还不能断言：
```

再运行校验器对答案：

```bash
python3 lab/record_contract.py
```

或只看一条：

```bash
python3 lab/record_contract.py cases/00-records/03-pit.json
```

## 十条记录

| 文件 | 应触发 |
|---|---|
| `01-clean.json` | 无。语义完整的内部假设 |
| `02-consensus.json` | 单家券商预测被命名为市场共识 |
| `03-pit.json` | 研究时点之后发布的一季报进入当时输入 |
| `04-bridge.json` | 内部调整没有逐项桥 |
| `05-evidence.json` | 证据指针只到机构名称和网站首页 |
| `06-recompute.json` | 派生值缺输入、公式与独立重算 |
| `07-model-restated.json` | 派生值由另一个语言模型复述，冒充独立计算 |
| `08-conflict.json` | 记录值与原文冲突，且没有声明任何变换 |
| `09-semantics.json` | 只保存了一个数字，对象、期间、单位、性质与时点全缺 |
| `10-negative-control.json` | **无。** 8家机构汇总，样本、方法、截点齐全 |

最后两条是重点。

`09` 说明「只保存数值」的记录会同时丢掉多少个可回答的问题。

`10` 是**负对照**：它被明确标为共识，看起来正踩在第2条的陷阱上，但样本家数、统计方法和截点都在，因此**不应降级**。一个在这里报警的验收器，会在真实项目里天天误报。知道何时不该报警，和知道何时必须报警，是同一项能力的两半。

## 边界

校验器只判断这条记录是否说清了自己是什么，不判断数字对不对。一条通过全部校验的记录，仍然可能基于错误的经营假设。

`expect_codes` 是教学用的答案字段，真实系统里的记录不会带它。
